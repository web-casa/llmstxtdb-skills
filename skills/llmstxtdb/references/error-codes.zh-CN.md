# 问题码参考（中文）

本文件由 llmstxtdb 检查器的修复手册生成（手册版本 v4），请勿手工修改；英文版见 `error-codes.md`。

每个问题码包含：标题、现象、为什么检查、对 AI 读取的影响、常见原因、修复步骤、验收方法。

## 规范符合性（提案条款）

只依据 llmstxt.org 提案。

### SPEC_H1_MISSING

**缺少一级标题（H1）**

- **现象：** 文件开头没有以 `# ` 起始的一级标题，检查器无法识别项目名。
- **为什么检查：** H1 是提案中唯一必需的元素，用来告诉读取方这份文件属于哪个项目。
- **对 AI 读取的影响：** 文件缺少提案约定的项目名称，读取方需要结合域名等其他信息判断这份文件属于哪个项目。
- **常见原因：**
  - 文件直接以正文或 blockquote 开头，漏写标题行
  - 把标题写成了 `## `（二级）或加粗文本 `**xx**`
  - 文件实际是 llms-full.txt 全文，被按索引文件检查
- **修复步骤：**
  1. 在文件第 1 行写 `# 项目名`（一个 #、一个空格、纯文本项目名）
  2. 确认全文只有一个 H1；正文层级从 `## ` 开始
  3. 若文件是全文版本（llms-full.txt），确认提交检查的是站点根部的索引文件 /llms.txt
- **验收：** 重新检查后 SPEC_H1_MISSING 消失，报告「规范符合性」H1 项为 PASS。

### SPEC_H1_MULTIPLE

**存在多个一级标题（H1）**

- **现象：** 文件中出现多个 `# ` 标题行，检查器无法确定唯一项目名。
- **为什么检查：** 提案要求只有一个 H1，读取方据此确定唯一的项目名和文档起点。
- **对 AI 读取的影响：** 提案只定义了一个 H1；出现多个时，不同解析实现对项目名和文档起点的理解可能不一致。
- **常见原因：**
  - 每个章节都用了 `# `（应从 `## ` 开始）
  - 从其他文档粘贴时带入了原有 H1
  - 模板残留：生成了多份骨架拼接在一起
- **修复步骤：**
  1. 保留第 1 行的项目名 H1，其余 `# ` 全部降级为 `## `（章节）或 `### `（小节）
  2. 检索文件中所有以 `# ` 开头的行：`grep -n '^# ' llms.txt`，应只剩 1 行
- **验收：** `grep -c '^# ' llms.txt` 输出 1；重新检查后 SPEC_H1_MULTIPLE 消失。

### SPEC_SUMMARY_EMPTY

**摘要 blockquote 为空**

- **现象：** H1 之后存在 `> ` 引用块，但内容为空或只有空白字符。
- **为什么检查：** 摘要提供项目概况，帮助读取方判断文档与当前任务是否相关；写了引用块就应该有内容。
- **对 AI 读取的影响：** 空的引用块不提供任何信息，读取方需要结合项目名、正文和条目来判断站点用途。
- **常见原因：**
  - 写了 `>` 占位但没填摘要内容
  - 模板里摘要段被误删只剩符号
- **修复步骤：**
  1. 在 H1 下方的 blockquote（`> ` 开头）写一句 ≤100 字的项目摘要：这是什么、给谁用、能做什么
- **验收：** 重新检查后 SPEC_SUMMARY_EMPTY 消失；摘要内容在报告 manifest 摘要字段可见。

### SPEC_SECTION_DEPTH

**章节层级超过 H2**

- **现象：** 章节标题使用了 `### ` 或更深层级；提案约定分组用 H2。
- **为什么检查：** 提案用 H2 划分条目分组，解析器按 H2 识别章节边界。
- **对 AI 读取的影响：** H3 及更深的标题不会被识别为章节，其下的条目可能被并入上一个 H2，或失去分组信息。
- **常见原因：**
  - 把小节直接当章节写成了 H3+
  - 从 README 粘贴带入深层级标题
- **修复步骤：**
  1. 把作为「章节分组」的深层标题提升为 `## `
  2. 确需保留的细分层级，并入所属 H2 章节正文或条目描述
- **验收：** 重新检查后 SPEC_SECTION_DEPTH 消失；章节列表在 manifest sections 中全部为 H2。

### SPEC_ENTRY_NOT_LINK

**条目不是 Markdown 链接**

- **现象：** 文件列表条目不是 `- [标题](URL)` 形式（纯文本、裸 URL 或代码样式）。
- **为什么检查：** 提案规定条目是 Markdown 链接，读取方靠链接地址去取对应页面。
- **对 AI 读取的影响：** 按提案解析时，这一行不会被识别为文档条目；依赖链接提取的工具拿不到这一行对应的页面地址。
- **常见原因：**
  - 条目写成了普通列表文本，没加方括号链接
  - 用反引号包裹了 URL（`<https://…>` 或 `` `url` ``）
  - 粘贴时 Markdown 链接语法损坏（括号/方括号缺失）
- **修复步骤：**
  1. 把每条条目改成 `- [标题](https://完整URL): 可选说明`
  2. URL 用完整绝对链接（含 https://），不要用尖括号或反引号包裹
  3. 确认它不该是条目的（如纯说明文字）——挪到摘要或正文中
- **验收：** 重新检查后 SPEC_ENTRY_NOT_LINK 消失；manifest entries 中全部条目带可解析 URL。

## 检查范围受限（不是提案条款）

不是提案条款，也不代表文件有缺陷：当前只在正文超过读取上限被截断时由在线检查器给出，表示规范检查只覆盖了已读到的部分。问题码沿用 SPEC_ 前缀是为了与既有报告兼容。

### SPEC_STRUCTURE_MISSING

**正文被截断，规范检查范围受限**

- **现象：** 响应体超过单次读取上限被截断，规范结论只基于已读到的部分。
- **为什么检查：** 检查索引结构是否可识别，并在正文被截断时说明检查范围受限。
- **对 AI 读取的影响：** 请结合证据判断：结构确实缺失时，读取方得不到项目名和条目；正文被截断时只检查了已读部分，不能据此断言原文件缺少结构。
- **常见原因：**
  - 把文档正文整段放进了索引文件
  - 条目过多，没有按产品或版本拆分
- **修复步骤：**
  1. 把索引文件缩减为项目名、摘要与条目链接，正文放到被链接的页面里
  2. 条目很多时按产品线或版本拆成子路径下的多份文件，再从根文件链接过去
  3. 重新检查
- **验收：** 报告不再带截断说明，规范结论基于完整内容。

## 实际可用性（部署后的观测）

对线上地址的实际观测，不属于提案条款。

### HTTP_STATUS

**HTTP 状态异常（文件不可达或返回错误）**

- **现象：** 检查器请求 llms.txt 时未拿到 200；具体网络层原因见证据中的子错误码。
- **为什么检查：** 先确认本次请求能否取得文件内容，再做结构与链接检查。
- **对 AI 读取的影响：** 本次请求没有取得可用内容，后续检查无法进行；其他读取方能否访问，取决于它们的网络环境和站点的访问规则。
- **常见原因：**
  - 文件不存在（404）或路径拼写错误
  - CDN/WAF 拦截了检查器请求（403/429/挑战页）
  - 服务器 5xx 或证书/网络故障（见子错误码 TLS/DNS/TIMEOUT 等）
  - 重定向链过长或成环
- **修复步骤：**
  1. 本机验证：`curl -I https://站点/llms.txt`，确认 200 与最终地址
  2. 看报告证据里的 redirectChain：文件实际落在哪个 origin——根路径 301 到别的域而文件只在旧域时会得到 404；路径写错、文件未部署、路由规则拦截也会如此
  3. 404 → 部署文件并核对路径大小写；5xx → 查服务端错误日志
  4. 403/429 → 在 WAF/CDN 放行合规爬虫的 UA 与网段，或放宽限流（提高允许的请求频率）
  5. 若证据带子错误码（TLS_ERROR/DNS_ERROR/TIMEOUT 等），按对应手册条目排查
- **验收：** 重新检查后 HTTP_STATUS 为 PASS，报告指标 HTTP 状态 = 200。

### CONTENT_TYPE

**Content-Type 不是文本（Markdown）**

- **现象：** 文件以 200 返回，但 Content-Type 不是文本类型（text/markdown 或 text/plain 均可）——如 text/html、application/octet-stream，工具端按非 Markdown 处理。
- **为什么检查：** 检查响应类型是否如实描述文件内容，减少客户端用错处理方式的可能。
- **对 AI 读取的影响：** 类型与内容不一致时，部分客户端可能按网页处理或不予解析；能否读出结构，还取决于正文和客户端实现。
- **常见原因：**
  - Web 服务器按扩展名未知文件回退为 octet-stream
  - 前端路由/SPA 把 /llms.txt 回退到 index.html
  - CDN 改写了响应头
- **修复步骤：**
  1. Nginx：`location = /llms.txt { default_type text/markdown; }` 或在 mime.types 增加 md→text/markdown
  2. Apache：`.htaccess` 加 `AddType text/markdown .txt`（仅对该路径）或用 ForceType
  3. 静态托管（Vercel/Netlify/OSS）：为该对象设置 Content-Type: text/markdown; charset=utf-8
  4. 确认 SPA 回退规则不吞 /llms.txt（静态文件优先于 history 回退）
- **验收：** `curl -sI https://站点/llms.txt | grep -i content-type` 显示 text/markdown 或 text/plain；重新检查 CONTENT_TYPE 为 PASS。

### SPA_DETECTED

**返回的是 SPA 首页而非 Markdown 文件**

- **现象：** HTTP 200 且看似可访问，但响应体是 HTML 应用外壳（无 Markdown 结构特征）。
- **为什么检查：** 单页应用常把不存在的路径一律返回首页，文件地址看似 200，实际返回的不是文件。
- **对 AI 读取的影响：** 本次响应命中了网页外壳的特征；如果实际返回的是应用页面，按文档读取的工具可能取不到预期内容，需结合正文确认。
- **常见原因：**
  - history 回退把不存在的 /llms.txt 重写到 index.html
  - 文件没被部署到服务器真实路径
  - 边缘路由把该路径代理到了前端应用
- **修复步骤：**
  1. 把 llms.txt 作为静态文件部署到 Web 根目录（与 index.html 同级），优先级高于 SPA 回退
  2. Nginx：`location = /llms.txt { try_files /llms.txt =404; }` 放在 SPA 回退之前
  3. 核对部署产物：构建流水线中确认该文件被复制（public/ 目录）
- **验收：** `curl -s https://站点/llms.txt | head -5` 显示 Markdown（# 开头）而非 <!DOCTYPE html>；重新检查 SPA_DETECTED 为 PASS。

### SOFT_404

**疑似 soft-404（主文件 200 但内容像错误页）**

- **现象：** llms.txt 本身返回 200，但内容嗅探像是错误页、空壳或无关内容。检查器只给 WARN 不定罪（自动识别有误报可能），需人工确认。
- **为什么检查：** 有些服务器对不存在的地址也返回 200，只靠状态码判断不出文件是否真的存在。
- **对 AI 读取的影响：** 如果返回的确实是错误页，读取方读到的会是错误页文本，而不是预期的文档。
- **常见原因：**
  - SPA/SSR 把 /llms.txt 路径回退到了应用外壳或错误页模板
  - 部署的是错误页/占位页而非真实文件
  - CDN 边缘缓存了错误响应
  - 误报：文件内容较空但确实是有效文档
- **修复步骤：**
  1. 打开 llms.txt 地址人工确认内容：确实是错误页/空壳 → 修部署（真实静态文件放到该路径，优先于 SPA 回退）
  2. 确认是有效文档（误报）→ 可忽略该警告，不影响规范符合性；复检两轮观察是否复现
  3. 若是边缘缓存问题 → 清除该路径 CDN 缓存后复检
- **验收：** 人工打开确认内容真实有效；重新检查后 SOFT_404 消失（或确认为误报并记录忽略决策）。

### FILE_SIZE

**文件体积超限**

- **现象：** 传输或解码后大小超过检查预算，响应被中止。
- **为什么检查：** 记录文件体积，并识别空文件或本次下载被截断的情况。
- **对 AI 读取的影响：** 空文件没有可读的正文；本次下载被截断时，未读到的部分无法检查，但不代表原文件缺少这些内容。
- **常见原因：**
  - 把全站内容堆进单个 llms.txt（应拆分或用 llms-full.txt 分册）
  - 混入了二进制/内嵌图片的 base64
  - 重复条目与冗余正文过多
- **修复步骤：**
  1. 索引文件只放「标题 + 链接 + 一句话说明」——超过几百 KB 通常说明把正文塞进了索引，拆分到子路径文档并在条目里链接
  2. 如需全文版，提供 llms-full.txt 并在索引中链接
  3. 去重：`sort llms.txt | uniq -d` 找重复段落
- **验收：** 重新检查后 FILE_SIZE 为 PASS，报告指标中解码大小在预算内。

### TOKEN_ESTIMATE

**Token 估算超限**

- **现象：** 文件 token 估算超过工具单次读取预算，AI 客户端可能截断或拒绝加载。
- **为什么检查：** 估算已读内容的 token 量，供站长评估它占用上下文的多少。
- **对 AI 读取的影响：** 估算值不等于任何模型的实际预算；空文件没有正文，截断时估算只覆盖已读到的部分。
- **常见原因：**
  - 正文冗长、重复或堆砌了低价值段落
  - 单文件承载了本应分册的全文内容
- **修复步骤：**
  1. 压缩正文：每条目描述 ≤1 句；删除与页面内容重复的段落
  2. 按主题拆分为多个子文档，索引只保留链接
  3. 为全文场景提供 llms-full.txt（见站内教程的分册策略）
- **验收：** 重新检查后 TOKEN_ESTIMATE 为 PASS，估算值在报告指标中可见且在预算内。

### LINK_HEALTH

**链接健康问题（失效或未能完成观测）**

- **现象：** 文件内链接存在失效候选（HTTP 错误/DNS 失效）或大量未能完成观测（超时/拦截）。
- **为什么检查：** 观测文档链接是否可访问，并区分失效候选与未能确认的链接。
- **对 AI 读取的影响：** 确认失效的链接无法提供对应页面；超时、限流、拦截或未查完只说明本轮访问受限，不能据此断言其他读取方也访问不到。
- **常见原因：**
  - 链接指向已下线/改版的页面（404/410）
  - 外链站点限流（429）或拦截自动化访问（401/403）
  - 目标域名过期或 DNS 配置错误
  - 链接拼写错误或使用相对路径
- **修复步骤：**
  1. 对报告「确定性失效候选」逐条处理：页面还在 → 改为新地址；已下线 → 移除条目
  2. 「受限/暂态」类先复核（浏览器打开确认），确认有效可保留，但关注后续轮次
  3. 批量核对本文件全部链接的 HTTP 状态后统一更新（逐条 curl -sI 即可）
  4. 新链接上线前先人工点一遍，避免带着死链发布
- **验收：** 重新检查后 LINK_HEALTH 无失效候选；「未能完成观测」数量明显下降或归零（复检两轮确认稳定）。

### MARKDOWN_NEGOTIATION

**Markdown 内容协商（可选增强）**

- **现象：** 抽测条目对 `Accept: text/markdown` 请求未返回 Markdown——站点文档页对 Agent 是 HTML 形态。
- **为什么检查：** 观测站点文档页能否按请求直接返回 Markdown，这是提案之外的一种做法。
- **对 AI 读取的影响：** 属于可选增强，非提案条款：本轮只抽测一个条目；未返回 Markdown 时，读取方需按实际响应类型处理；没有取得可分类的响应时，无法判断这项能力。
- **常见原因：**
  - 站点未开启边缘 HTML→Markdown 转换（如 Cloudflare AI Crawl Control 的 Markdown for Agents，Pro 及以上可用）
  - 文档页本身已是 Markdown 文件时该检查为通过，无需处理
  - 未开启不属于错误：该能力可选，不影响任何评分与结论
- **修复步骤：**
  1. 使用 Cloudflare：控制台选择区域 → AI Crawl Control → 开启 Markdown for Agents（或用配置规则对 docs 子域开启）
  2. 非 Cloudflare 部署：为文档路由提供 text/markdown 内容协商（如静态站点同时输出 .md 与页面，或网关层做 HTML→Markdown 转换）
  3. 确认开启后响应 Content-Type 为 text/markdown 且保留 Vary: Accept
- **验收：** 对条目页 `curl -H "Accept: text/markdown" <url>` 返回 text/markdown；重新检查后该项结论变为支持。

## 抓取（网络与安全）

请求没有完成的原因。其中一部分是检查器自身的限制，不代表文件有问题。

### SAFE_BLOCKED_SCHEME

**链接协议非 http(s)**

- **现象：** 文件中的链接使用了 ftp:/javascript:/data: 等协议，安全策略拒绝抓取。
- **为什么检查：** 检查器只抓取 http 和 https 地址。
- **对 AI 读取的影响：** 本站没有请求这个地址；其他工具能否读取 ftp、data 等协议的链接，取决于各自的支持范围和安全策略。
- **常见原因：**
  - 条目误用了 mailto:/ftp: 或相对协议 //
  - 被注入的恶意或垃圾链接
- **修复步骤：**
  1. 把条目全部改为 https:// 绝对链接；删除非文档类协议条目
  2. 检索：`grep -nE '\b(ftp|javascript|data):' llms.txt`
- **验收：** 重新检查后 SAFE_BLOCKED_SCHEME 消失，manifest 条目全部为 https。

### SAFE_BLOCKED_PORT

**链接端口非常规（非 80/443）**

- **现象：** 链接带 :8080/:3000 等端口，安全策略拒绝。
- **为什么检查：** 检查器只访问 80 和 443 端口，避免被用来探测其他服务。
- **对 AI 读取的影响：** 本站没有请求这个地址；非常规端口上的服务是否可达，取决于读取方的网络环境和安全策略。
- **常见原因：**
  - 把内网/开发环境地址写进了文件（localhost:3000）
  - 服务通过非标端口对外暴露
- **修复步骤：**
  1. 改用标准 443 端口的公网域名（配置反向代理）
  2. 删除开发/内网地址条目——它们本就不该出现在公开文档里
- **验收：** 文件中不再有带非标端口的链接；重新检查后该项消失。

### SAFE_BLOCKED_CREDENTIALS

**链接内嵌凭据（user:pass@）**

- **现象：** URL 携带用户名密码（https://user:pass@host/…），安全策略拒绝且凭据会公开泄露。
- **为什么检查：** 检查器拒绝抓取包含用户名或密码的地址，避免处理或传播凭据。
- **对 AI 读取的影响：** 本次没有请求含凭据的目标；如果这个地址出现在公开文件里，凭据可能已经泄露，应移除并更换。
- **常见原因：**
  - 从带鉴权的内网系统复制链接时带上了 userinfo
  - API key 直接写在 URL 里
- **修复步骤：**
  1. 立即移除 URL 中的凭据部分；已泄露的密码/key 全部轮换
  2. 需要鉴权的内容不应放进公开文档索引
- **验收：** `grep -n '@' llms.txt` 核对无凭据残留；重新检查后该项消失。

### SAFE_BLOCKED_PRIVATE

**链接指向私网/保留地址**

- **现象：** 链接解析到 127.0.0.1、10.x、192.168.x、169.254.x 等私有地址（SSRF 防护拒绝）。
- **为什么检查：** 检查器拒绝访问解析结果中含私网、保留或其他受限地址的目标，防止触及受保护的网络。
- **对 AI 读取的影响：** 本次请求被地址安全策略阻止；只在内网可用的目标通常无法被外部读取方访问，但这一项不能证明目标对所有读取方都失效。
- **常见原因：**
  - 条目写的是内网/本机地址
  - 公网域名的 DNS 被配置成私有 IP（解析劫持或误配）
- **修复步骤：**
  1. 把内网地址替换为对应的公网域名；仅内网可用的服务不收录
  2. `dig +short 域名` 确认解析到公网 IP；DNS 误配在服务商处修正
- **验收：** 所有链接解析为公网地址；重新检查后 SAFE_BLOCKED_PRIVATE 消失。

### SAFE_BLOCKED_SELF

**链接指向检查服务自身**

- **现象：** 链接解析到本检查部署的地址，为避免自引用环被拒绝。
- **为什么检查：** 检查器不抓取指向自身的地址，避免形成自引用。
- **对 AI 读取的影响：** 这是本次检查未能完成，不代表文件有问题；该链接本轮没有被观测。
- **常见原因：**
  - 条目误写了检查工具的地址（复制错 URL）
- **修复步骤：**
  1. 核对并改为目标站点的真实文档地址
- **验收：** 重新检查后该项消失。

### SAFE_BLOCKED_HOST

**来源不在抓取白名单（应用层拒绝）**

- **现象：** 检查器对特定功能的抓取目标做了应用层白名单限制，该请求被前置拒绝（该跳零请求）。
- **为什么检查：** 部分功能只允许抓取白名单内的来源，其余请求在发出前被拒绝。
- **对 AI 读取的影响：** 这是本次检查未能完成，不代表文件有问题；该地址本轮没有被请求。
- **常见原因：**
  - 资源托管在白名单外的第三方域（多为站点图标等附属资源）
  - 附属资源依赖未随主检查目标放行
- **修复步骤：**
  1. 此类拒绝通常针对检查器的附属抓取（如图标），不影响 llms.txt 主文件检查结论
  2. 若主文件检查受影响，把资源迁移到主域或 CDN 标准域后重试
- **验收：** 重新检查后相关候选可正常抓取（或确认仅附属资源受限、主报告不受影响）。

### DNS_ERROR

**DNS 解析失败**

- **现象：** 域名无法解析为 IP，请求未发出。
- **为什么检查：** 域名解析是请求的第一步，解析不到地址，请求就无法发出。
- **对 AI 读取的影响：** 本次未能解析目标域名，因此没有取得目标内容；如果是暂态的解析错误，重试可能恢复，其他读取方的结果也可能不同。
- **常见原因：**
  - 域名拼写错误或已过期
  - DNS 记录被误删/未生效（新解析延迟）
  - 仅内网可解析的私有域名
- **修复步骤：**
  1. `dig +short 域名` 或 `nslookup 域名` 验证公网解析
  2. 域名过期 → 续费；记录错误 → 在 DNS 服务商修正 A/CNAME
  3. 内网域名改为公网可解析，或放弃对该地址的公开收录
- **验收：** 公网环境 `dig` 正常返回记录；重新检查后 DNS_ERROR 消失。

### TLS_ERROR

**TLS 证书或握手失败**

- **现象：** HTTPS 连接建立失败：证书无效、过期、域名不匹配或协议不受支持。
- **为什么检查：** HTTPS 握手失败时，本检查器会中止连接，不做容错。
- **对 AI 读取的影响：** 本检查器因证书或握手错误没有取得目标内容；其他客户端是否同样失败，取决于它们的证书校验和协议支持。
- **常见原因：**
  - 证书过期未续期
  - 证书与域名不匹配（含缺少 www/SAN）
  - 仅支持旧 TLS 版本或密码套件
  - 证书链不完整（缺中间证书）
- **修复步骤：**
  1. `openssl s_client -connect 域名:443 -servername 域名 </dev/null 2>/dev/null | openssl x509 -noout -dates -subject` 查看证书状态
  2. 续期证书（Let's Encrypt：`certbot renew`）；确保证书覆盖所有服务域名（含 www）
  3. 启用 TLS 1.2+；用 `openssl s_client` 确认完整证书链（缺中间证书到 SSL Labs 检测）
- **验收：** `curl -vI https://站点/llms.txt` 无 SSL 错误；重新检查后 TLS_ERROR 消失。

### NETWORK_ERROR

**网络错误（连接失败/重置）**

- **现象：** TCP 连接失败、被重置或读取出错，非 DNS/TLS 的网络层故障。
- **为什么检查：** 记录本次连接或读取失败，原因可能来自服务端、网络路径或检查任务被中止。
- **对 AI 读取的影响：** 本次没有取得目标内容；这类失败常是暂时的，其他读取方在别的时间和网络下结果可能不同。
- **常见原因：**
  - 源站对非浏览器请求做了拦截（WAF/防爬规则——静态文本文件最常见的失败原因）
  - 服务器宕机或进程未监听 80/443
  - 防火墙/安全组拦截了来源网段
  - 连接被中间设备重置
- **修复步骤：**
  1. 在 WAF/防爬配置里放行对 /llms.txt 的普通 GET
  2. `curl -v https://站点/llms.txt` 区分「全挂」还是「部分来源被拦」；注意本机 curl 通 ≠ 公网通
  3. 服务未监听 → 启动 Web 服务并检查端口；防火墙 → 放行 80/443
- **验收：** 从外部网络重新检查，NETWORK_ERROR 消失且 HTTP 状态 200。

### TIMEOUT

**请求超时**

- **现象：** 服务器在预算时间内未返回完整响应。
- **为什么检查：** 为单个请求和整个检查任务设置等待上限，避免检查无限持续。
- **对 AI 读取的影响：** 本次请求或任务达到了时间上限，没有取得完整的目标内容；这不等于链接失效，也不代表其他读取方会超时。
- **常见原因：**
  - 服务器过载或后端阻塞
  - 动态路由回退大文件（静态文件直达能力不足）
  - 网络链路抖动（跨国/弱网）
- **修复步骤：**
  1. 压测接口耗时：`time curl -s https://站点/llms.txt -o /dev/null`；>5s 先查服务端慢查询/过载
  2. 为静态文件开启 CDN 边缘缓存，避免回源
  3. 缩小文件体积（见 FILE_SIZE 手册），降低传输时间
- **验收：** 重新检查两轮，TIMEOUT 消失且总检查能在预算内完成。

### TOO_LARGE

**响应体超限（流式中止）**

- **现象：** 解压后的响应体超过单文件上限（当前 2MB 解码后），检查器流式中止。报告只声明「已截断」的事实，不对不完整内容推断删除。
- **为什么检查：** 保留的错误码：解压后超过单文件上限时中止读取；当前这类情况以截断标注和体积、token 两项告警呈现。
- **对 AI 读取的影响：** 本次超过读取上限的部分没有被读到；报告结论只基于已读到的部分，不对未读内容作推断。
- **常见原因：**
  - 单文件体积超上限（同 FILE_SIZE）
  - 误把压缩包/导出文件放在 llms.txt 路径
- **修复步骤：**
  1. 核对 `curl -s https://站点/llms.txt | wc -c`，按 FILE_SIZE 手册瘦身或拆分
- **验收：** 重新检查后 TOO_LARGE 消失，解码大小在指标中可见且低于上限。

### TOO_MANY_REDIRECTS

**重定向过多**

- **现象：** 重定向链超过 3 跳（检查器跟随上限），常见为 http→https→www→备用域名的连环跳。
- **为什么检查：** 读取方跟随重定向的次数有限，链条太长会被放弃。
- **对 AI 读取的影响：** 超过跟随上限时请求中止，读取方拿不到最终的文件。
- **常见原因：**
  - http→https 与 非www→www 规则互相打架形成环
  - CDN 与源站都做重定向，叠加成链
- **修复步骤：**
  1. 确定唯一规范形式（如 https://www.example.com），所有变体一条规则 301 到它
  2. `curl -sIL https://站点/llms.txt | grep -i location` 查看重定向链，消除中间跳
  3. CDN 侧关闭与源站重复的重定向规则（只留一层）
- **验收：** 重定向链 ≤2 跳直达 200；重新检查后 TOO_MANY_REDIRECTS 消失。

### RATE_LIMITED_ORIGIN

**站点对本检查器限流（429）**

- **现象：** 服务器返回 429/Retry-After，检查被暂停。这是「未查」不是「结论」——本轮不产生可用性判定。
- **为什么检查：** 对方服务器要求放慢请求，检查器会遵守并暂停。
- **对 AI 读取的影响：** 这是本次检查未能完成，不代表文件有问题；若同样的限流规则作用于其他自动化读取方，它们也会被暂时拒绝。
- **常见原因：**
  - WAF/网关对自动化请求的速率阈值过低
  - 短时间内多轮检查叠加触发限流
- **修复步骤：**
  1. 按工具提示的 Retry-After 等待窗口过期再提交；降低检查频率，避免连续手动触发
  2. 站点是站长自己的 → 可在自有网关为合规只读抓取提高限额或放行（属站点管理动作，非绕过）
  3. 不要用更换 IP 等方式绕过——那是对站点意愿的不尊重（教程口径）
- **验收：** 暂停窗口过后重新检查，本轮不再出现 RATE_LIMITED_ORIGIN，检查完整执行。

### BUDGET_EXCEEDED

**请求预算耗尽**

- **现象：** 单次检查的逐跳请求预算用完，后续探测被主动放弃（常见于链接数极多的文件）。
- **为什么检查：** 单次检查的请求数有上限，用完后剩余的探测会主动放弃。
- **对 AI 读取的影响：** 这是本次检查未能完成，不代表文件有问题；未探测的链接状态未知。
- **常见原因：**
  - 文件链接条目远超单轮预算，抽样与预算同时吃紧
  - 大量重定向/多跳链接放大了请求数
- **修复步骤：**
  1. 精简条目：合并重复链接、移除低价值外链
  2. 减少链接的重定向跳数（直接指向最终地址）
  3. 链接确实很多时接受抽样口径——报告 coverage 会如实标注覆盖规则
- **验收：** 重新检查后 BUDGET_EXCEEDED 消失（或 coverage 标注为抽样且完成率高）。

### SAFE_BLOCKED

**链接被安全策略阻止（归类观测）**

- **现象：** 单个链接的抓取被安全策略拒绝（协议/端口/私网/重定向越界等，逐链接观测归类）。
- **为什么检查：** 记录逐链接抓取被策略阻止、重定向超限或回退复核未完成的情况。
- **对 AI 读取的影响：** 本轮未能确认该链接是否可用，原因可能是策略阻止、重定向超限或复核中断；已有的探测结果也可能未获复核，不能据此断言链接失效。
- **常见原因：**
  - 链接指向内网、非常规端口或非 http(s) 协议
  - 重定向跳出允许范围（如跳到私网）
- **修复步骤：**
  1. 按报告链接观测中的具体 URL 逐条核对，替换为公网 https 直链
  2. 被劫持/误配的域名先修复解析，再恢复条目
- **验收：** 重新检查后 SAFE_BLOCKED 类观测消失或降为 0。

## 编辑建议（非提案条款）

写法上的建议，不影响规范结论，可以全部不采纳。

### ADVICE_SUMMARY_MISSING

**缺少摘要 blockquote（建议）**

- **现象：** H1 后没有 `> ` 摘要段。提案中摘要是可选的，但摘要能显著提升 AI 对站点的理解。
- **为什么检查：** 摘要帮助读取方在读条目之前先判断站点与任务是否相关。
- **对 AI 读取的影响：** 属于编辑建议，非提案条款：没有摘要时，读取方需要结合项目名、正文和条目来判断站点用途。
- **常见原因：**
  - 生成模板未包含摘要段
- **修复步骤：**
  1. 在 H1 下加一行 `> 一句话摘要`：项目是什么、给谁用、核心能力（≤100 字）
- **验收：** 重新检查后该建议消失，manifest summary 字段非空。

### ADVICE_NO_SECTIONS

**无 H2 章节分组（建议）**

- **现象：** 全部条目平铺没有 `## ` 分组。章节是可选的，但分组能改善 AI 对内容结构的导航。
- **为什么检查：** 分组让读取方能按任务只取相关的一组条目。
- **对 AI 读取的影响：** 属于编辑建议，非提案条款：条目平铺时，缺少按主题分组的导航信息。
- **常见原因：**
  - 条目少时偷懒平铺；或条目多时未整理
- **修复步骤：**
  1. 按主题建 `## Docs`/`## Guides`/`## API` 等章节，把条目归组
  2. 条目确实很少（≤5 条）时平铺也可接受，此建议可忽略
- **验收：** 重新检查后该建议消失（或确认忽略的决策被记录）。

### ADVICE_ENTRY_NO_DESCRIPTION

**条目缺少一句话说明（建议）**

- **现象：** 条目只有链接没有 `: 说明`，AI 无法预判页面内容。
- **为什么检查：** 一句话说明帮助读取方在打开页面之前初步判断它的用途。
- **对 AI 读取的影响：** 属于编辑建议，非提案条款：没有说明时，可用于判断页面用途的信息较少，读取方可能需要打开页面才能确认。
- **常见原因：**
  - 批量导入时只抓了标题与 URL
- **修复步骤：**
  1. 为每条条目补 `: 说明`（≤1 句，说明该页回答什么问题）
- **验收：** 重新检查后该建议消失。

### ADVICE_RELATIVE_URL

**条目使用相对 URL（建议）**

- **现象：** 条目链接是 /docs/… 相对路径。提案未禁止，但相对链接依赖读取方补全域名，部分客户端会解析失败。
- **为什么检查：** 提示没有写成 http(s) 绝对地址的条目，复核它是否需要基准地址或其他协议支持。
- **对 AI 读取的影响：** 属于编辑建议，非提案条款：相对地址需要结合文件地址解析，非 http(s) 地址需要相应的协议支持；能否使用取决于读取方的实现。
- **常见原因：**
  - 生成时直接使用了站内路径
- **修复步骤：**
  1. 补全为 `https://域名/docs/…` 绝对链接
- **验收：** 文件中不再有以 / 开头的条目链接；重新检查后该建议消失。
